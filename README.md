## 0.21.14 — 정확도 우선 원본 후보 선별 및 사용자 피드백 저장 (최종 컴파일 복구)

- Cloud Vision 페이지 내부에서 full/partial image match 근거가 있는 소셜 게시물을 우선 제시. 단순 관련 웹페이지는 최대 3개만 별도 참고로 표시하고 자동 영상 다운로드/검증 불가.

- 사용자 직접 제공 원본 사례는 검색 실패나 재검색으로 제거되지 않음. 오탐 줄이기 중심이며 이미지 색인 및 플랫폼 영상 스트림 제한은 해결되지 않음.
- 0.21.12~0.21.13 빌드 실패의 원인이던 손상된 데이터 복원 함수, 변수명 충돌, 소스 파일 끝의 중복 BenchApi 클래스를 복구. 고정 서명 앱 검증을 다시 실행.
## 0.21.13 — 원본 검색 오탐 감소 및 검증 실패 원인 보강

- Cloud Vision 웹페이지 후보 중 페이지 내부 이미지 완전/부분 일치 근거가 있는 게시물을 우선 표시·자동 검증. 단순 연관 페이지는 최대 3건의 수동 참고만 표시하며 자동 영상 다운로드하지 않음.
- 후보별 '원본 아님' 버튼: 잘못된 링크를 해당 벤치마킹 영상에서 영속적으로 제외, 이후 검색에서도 무시. 제외 목록 초기화 가능.
- 후보별 '원본 확인·저장' 버튼: 사용자가 발견한 실제 원본을 별도 확정, 이후 검색/앱 재시작에도 보존. 자동 발견 성공률에 섞지 않음.
- 원본 검색 진단에서 직접 매칭 후보와 연관 페이지만 있는 후보를 구분. 원본 아닌 웹페이지가 영상 검증 슬롯을 소모하지 않도록 개선.
- 이전 0.21.12에서 저장 상태 파서 일부가 손상되고 search(manual:) 옵션과 지역 변수가 겹친 컴파일 오류를 확인하여 전체 데이터 역직렬화 함수와 변수명을 복구. 0.21.13은 수정된 소스로 다시 정적 검사·테스트·서명 빌드 검증.
- 중요: Google Cloud Vision이 실제 원본 동영상을 웹 이미지에 색인하지 않았다면 여전히 못 찾을 수 있음. 이 업데이트는 근거가 약한 후보를 줄이고 사용자 판정 내역을 보존하는 개선이지, 새로운 원본 발굴 엔진을 구현한 것은 아님.
## 0.21.12 — 원본 탐색 정확도 개선: 직접 이미지 일치 우선·오탐 피드백 저장

- 사용자가 원본 릴스를 실제로 찾은 경우도 있으나, 앱에서 자동으로 보여준 후보 상당수는 관련 없는 영상으로 확인됐음. 웹페이지가 이미지 검색에 나타난 사실과 해당 페이지에 동일한 영상이 있다는 사실은 다름.

- 후보 카드에서 '원본 확인·저장' 선택 시 확인창 후 사용자 확인 원본으로 별도 저장. 자동 검색 성공으로 잘못 계산하지 않고 이후 재검색에서 보존.

## 0.21.10 — 한국어 OCR 기반 자막 회피 + 비슷한 길이 원본 후보만 자동 확인

- 사용자의 실기기 스크린샷에는 검색용 이미지 중앙에 한국어 자막이 여전히 남았고, 영상 길이 조건이 없어 관계없는 영상 후보가 섞이는 문제가 반복됨. 기존 고정 상단 30%·하단 35% 크롭은 OCR 자막 감지 방식이 아니었음.
- 검색용 실제 프레임에서 앱에 이미 포함된 Google ML Kit Korean Text Recognition을 실행해 글자 bounding box를 검출. 글자 경계에 여유 영역을 둔 뒤 겹치지 않는 직사각형 부분만 Google Cloud Vision 역이미지 검색에 업로드. 자막과 겹치지 않는 프레임이 3장 미만이면 그 사실을 명시하고 중지하므로, 고정 크롭을 자막 제거 성공이라고 표시하지 않음.
- 검색 장면은 영상 전체에 걸쳐 6개 시점을 분산 선택(12개 시점 중 예비 시점을 활용), 장면마다 자막을 피할 수 있는 영역 위치·크기를 `bounds`로 저장. 후보 동영상의 프레임 지문을 비교할 때 동일 영역 좌표로 자르도록 동기화. 같은 후보 타임스탬프에서 나온 여러 공간 크롭이 서로 다른 장면으로 중복 계산되지 않도록 검사.
- 원본 길이가 42초일 때 ±20% 정수 반올림 허용(최소 ±3초), 실무적으로 33~51초 안에서 우선 자동 검증. YouTube Data API `videos.list(part=contentDetails)`의 실제 `duration`으로 후보를 한 번에 조회하고 불일치/확인 불가능한 영상은 스트림 다운로드하지 않음. TikTok은 기존 메타데이터에서 다운로드 전 확인 가능한 길이를 같은 범위로 제한하고 실제 다운로드 후에도 검사. 재생시간 일치는 **내용 일치 증거가 아니며** 실제 영상 프레임/자막 검사도 통과해야 제작 가능.
- 사용자가 직접 영상 원본 파일을 선택하거나 Google Lens로 이미지를 검색하는 기능은 계속 제공. Google Cloud Vision 자체가 웹에 색인되지 않은 원본을 찾을 수 없는 한계는 그대로 존재함.
- 구현: `tool/BenchmarkOcrCrop.kt` 신규, `tool/BenchmarkFrameExtractor.kt` OCR 및 bounds 동기화, `tool/benchmark_duration.dart` YouTube ISO8601 재생시간 파싱/사전 조회, `tool/benchmark_oneclick.dart` 길이 기준, `tool/benchmark_ui.dart` 연결, Android `MainActivity.kt` native 후보 bounds 수신, `tool/benchmark_tests.dart` 검증 테스트. 버전 소스 통합 `tool/patch_ocr_duration.py`, 분산 시점 `tool/patch_ocr_spread.py`.
- **주요 한계:** ML Kit OCR이 일부 그래픽/효과 자막을 인식하지 못할 수 있고 OCR 위치와 겹치지 않는 영역을 찾지 못하는 영상은 검색 실패할 수 있음. 영상 전체 대신 작은 부분을 검색하면 검색 품질이 달라질 수 있음. 후보 영상 스트림 접근이 차단되는 문제는 이번 패치에서 해결되지 않음. 실기기 실측 전 정확도 향상을 보장하지 않음.

## 0.21.8 — 이미지 검색 엔진 한계에 대비한 영상 장면 Google Lens 검색 공유

- 벤치마킹 쇼츠 실기기 검증에서 `Cloud Vision WEB_DETECTION` 결과가 0건이거나, 검색 웹페이지가 여러 개 발견되어도 실제 원본 게시물은 찾지 못하는 사례를 확인했습니다. 이는 웹 이미지 색인과 원본 동영상 색인이 별개이기 때문이며, 단순 점수·후보 개수 조정으로 원본 발견을 보장하지 않습니다.
- 원클릭 벤치마킹 탐색 후 **'Cloud Vision 검색 장면' 이미지 각각을 터치하면 전체 원본 프레임을 Android 이미지 공유 화면으로 보냅니다.** Google Lens 등 이미지 검색 앱에서 배경·물체·인물 등 텍스트를 피한 영역을 선택해 검색할 수 있습니다. 일부 기기는 Lens가 공유 대상으로 직접 나오지 않을 수 있으니 Google 또는 사진 앱에서 Lens 검색을 선택합니다.
- Vision API용 검색 이미지는 기존대로 중앙 크롭을 사용하고, **Lens 검색용에는 자르기 전 실제 프레임**을 전달합니다. 기기에서 공유할 때에만 cache/lens-frames 에 임시 JPEG를 저장하고 AndroidX FileProvider를 통해 읽기 권한을 제공합니다. 앱 내부 다른 파일에 접근할 수 없도록 해당 캐시 하위 경로만 허용합니다.
- Android는 이미지 검색 앱 선택 및 검색 결과 확인이 필요합니다. **완전 무인 원본 자동 발굴 기능이 아니며, 정확한 원본 발견을 보장하지 않습니다.** 추가 유료 API 키는 사용하지 않습니다.
- 기존 Cloud Vision 자동 탐색·후보 실제 영상 교차검증·자막 의심 검사·템플릿 편집 기능과 상위 50개 캐시는 유지합니다.
- 소스: `tool/benchmark_ui.dart`, `tool/BenchmarkFrameExtractor.kt`, `native/android/MainActivity.kt`, `native/android/AndroidManifest.xml`, `native/android/benchmark_frame_paths.xml`; `tool/bootstrap.py` 이미지 공유용 리소스 설치. 패치 `tool/patch_lens_fallback.py`.

## 0.21.3 — 이미지 역검색 '원본 없음' 진단 및 자막 포함 장면 개선

- 기존 사진처럼 **스트림/프레임 추출은 되지만 결과가 0개인 사례**를 구분합니다. 원본을 찾았다는 근거 없이 비슷한 동영상만 추천하지 않습니다.
- Cloud Vision Web Detection의 실제 응답에서 **이미지 일치 웹페이지 수, 페이지 내 직접 이미지 일치 근거 수, TikTok/Instagram/YouTube 단일 게시물 수, 원본 동영상 검사 건수, 불일치·자막 의심·실패 건수**를 확인해 카드에 표시합니다. 동일 메시지는 앱 전용 상태 JSON에 저장되므로 화면 재실행 후에도 원인을 확인할 수 있습니다.
- 세로 영상 프레임은 이전의 상단/하단 각각 18% 제거보다 더 적극적으로 **상단 30%, 하단 35%**를 잘라 중앙의 액션 영역을 역검색합니다. 가로 영상은 상단 16%, 하단 18% 제거. 참조/후보 영상 비교에는 동일 중심 영역을 사용합니다. 일부 핵심 장면이 잘릴 수 있으므로 실제 이미지 미리보기로 확인해야 합니다.
- 기존 상위 50개 조회수·랜덤 추첨 기록 유지. 기존 텍스트 검색/Tavily, 권한 입력은 다시 추가하지 않습니다.
- **중요한 한계:** Google Cloud Vision은 '이미지와 일치하는 웹페이지'를 찾는 도구이며 영상 원작자 추적 API가 아닙니다. 웹 이미지 색인에 원본 게시물이 없으면 자동 검색 결과가 계속 0개일 수 있습니다. 원본 자동 확정 및 자막 판별 정확도는 실기기 비교 검증 전입니다.
- 소스: `tool/vision_reverse.dart`, `tool/benchmark_oneclick.dart`, `tool/benchmark_ui.dart`, `tool/benchmark_data.dart`, `tool/BenchmarkFrameExtractor.kt`; 테스트 `tool/benchmark_tests.dart`.
- 패치 스크립트 `tool/patch_vision_diagnostics.py`. 이번 버전은 원클릭 작업 원인 진단과 자막 회피 개선이지 검색 적중률을 보장하는 변경이 아닙니다.

## 0.21.1 — 원클릭 벤치마킹 → 원본 동영상 비교 → 기존 템플릿

- **전체 원클릭 · 랜덤 1개 → 원본 검증 → 템플릿** 버튼을 벤치마킹 화면에 추가. 한번 누르면 기존에 저장된 채널별 상위 50개에서 미추첨 영상을 무작위 선정하고, YouTube 스트림에서 실제 6개 프레임을 추출합니다.
- Cloud Vision WEB_DETECTION 이미지만으로 **1개 프레임에서 발견된 개별 게시물도 탐색 후보로 수집**, 기존 3프레임 검색 선별 조건 제거. 단순 이미지 검색 후보를 원본이라고 확정하지 않습니다.
- 최대 5개 검색 후보 중 YouTube/TikTok 영상을 앱 내부에서 실제로 내려받아 **중앙 영역 64비트 이미지 지문(dHash)을 비교**합니다. 참조 영상과 후보의 서로 다른 2개 이상 장면이 가깝고, 강한 일치가 하나 이상 있을 때만 영상 장면 일치로 간주합니다. 단일 장면·약한 유사성만으로는 자동 통과 불가.
- 기존 Android ML Kit 한국어 OCR 모듈 `OriginalTextScanner`로 후보 영상 상/하단의 반복 글씨를 검사합니다. 후보에 자막/제목 합성 의심 신호가 있으면 자동 제작 제외합니다. OCR 누락, 자연스러운 글씨에 의한 오탐 등 가능성이 남아 있으므로 게시 전에 수동 확인이 필요합니다.
- **확인된 TikTok 원본**은 자동으로 기존 Clip 수집함에 등록하고 Gemini AI 제목/자막 생성이 시작되는 EditorScreen으로 전환됩니다. Google Vision이 원본을 색인하지 않았거나 후보가 없으면 없는 그대로 표시하고, 불일치·자막 의심 이유를 화면에 표시합니다.
- 원본 후보가 YouTube인 경우 자동 검증은 가능하지만, 프레임 분석에 사용하는 video-only 스트림은 음성이 없어 최종 편집기 원본으로 자동 등록하지 않습니다. Instagram 후보는 이 버전에서 자동 영상 다운로드/검증을 지원하지 않으므로 수동 확인 대상으로 남깁니다.
- 자동 탐색은 한 영상의 후보 최대 5개까지만 검사해 무제한 요청·저장소 사용을 방지합니다. 검증에 실패한 TikTok 다운로드 파일은 정리하며, YouTube 스트림 임시 영상은 프레임 분석 후 삭제합니다. 조회수 상위50 및 랜덤 추첨 캐시는 계속 사용합니다.
- 원본이라고 판정된 영상이라도 최초 제작자나 이용 권한이 입증되는 것은 아니며, **자동 업로드/게시를 수행하지 않습니다.**
- 구현: `lib/benchmark_oneclick.dart` `lib/benchmark_ui.dart` `lib/vision_reverse.dart` `native/android/BenchmarkFrameExtractor.kt` `native/android/MainActivity.kt`; 테스트 `test/benchmark_test.dart`; 변경 스크립트 `tool/patch_oneclick.py` 및 `tool/patch_oneclick_finish.py`.
- **모의 테스트 및 빌드가 성공해도 실기기 원본 탐색의 발견률·적중률은 별개로 검증해야 합니다.** Cloud Vision의 영상 색인 한계와 비공식 YouTube 스트림 접근 제한이 존재합니다.

## 0.20.4 — 벤치마킹 원본 역이미지 오탐 차단 및 실제 검색 프레임 미리보기

- 기존 `pagesWithMatchingImages` 단순 등장·구식 `score` 누적 방식은 관계없는 유튜브·인스타그램 게시물을 원본 후보로 표시할 수 있어 제거했습니다.

- 실제 검색에 업로드한 6개 프레임을 벤치마킹 카드에서 미리 볼 수 있어, 스트림 추출 자체가 잘못된 영상이거나 자막이 남았는지 확인할 수 있습니다.
- 원본 참조 영상 프레임 **전체 6장 모두** 상하단·일부 좌우의 오버레이 의심 영역을 잘라 검색하도록 통일했습니다. 실제 영상의 특성에 따라 중요한 장면이 잘릴 수 있으니 미리보기에서 확인합니다.
- 예전 결과 출처 `프레임 역이미지 검색`은 신뢰할 수 없어 캐시에서 제거합니다. 직접 추가한 링크, 채널별 상위 50개 영상과 추첨 이력은 보존합니다.
- Google Vision 페이지 일치 결과가 원본 영상임을 보장하지는 않습니다. 원본 여부와 재편집 자막 여부는 별도 확인이 필요하며, 이번 필터는 오탐을 줄이기 위해 *회수율을 희생하는* 보수적 기준입니다.
- 구현: `lib/vision_reverse.dart`, `lib/benchmark_ui.dart`, `native/android/BenchmarkFrameExtractor.kt`, `test/benchmark_test.dart`; 수정 패치 `tool/patch_vision_precision.py`.

- 편집 화면의 **AI 설정(열쇠)**에서 Gemini API 키를 입력합니다. [Google AI Studio 키 발급](https://aistudio.google.com/apikey). 결제를 연결하지 않은 무료 프로젝트 키를 사용하세요. 기본 모델은 gemini-3.1-flash-lite이며 설정에서 변경할 수 있습니다.
- **AI 제목·자막 생성 → 결과 확인 → 적용**. 원본 영상·소리를 Google Files API로 업로드하고 선택 구간의 두 줄 제목과 장면별 상황 자막을 요청합니다. 무료 한도는 프로젝트/모델에 따라 달라지며 무제한이 아닙니다. 결제가 연결된 프로젝트 키는 비용이 발생할 수 있습니다. 앱이 유료 모델로 자동 전환하지는 않습니다.
- 무료 티어 입력·출력은 Google 제품 개선에 사용될 수 있습니다. 민감한 영상은 전송하지 마세요. 업로드는 200MB까지, 생성 작업은 4분 제한입니다. 생성 후 업로드 파일 삭제를 시도하며 실패 시 Google의 파일 만료 정책을 따릅니다.
- 생성 결과는 적용하기 전 확인합니다. 적용 후 자막의 문구·시작/종료 시간 수정, 장면 미리보기, 추가/삭제가 가능합니다. 타임코드는 원본 영상 기준 초입니다. 겹치는 자막은 허용하지 않습니다. 재생과 MP4 저장에 같은 타이밍을 적용하고 선택 구간을 바꾸면 구간 밖 자막은 내보내지 않습니다.
- 기존 고정 자막 프로젝트는 보존합니다. 시간별 자막이 있으면 고정 자막 대신 시간별 자막을 사용합니다. 참고 영상 제목/폰트/세로 포맷은 유지합니다.
- API 키는 Android Keystore AES-GCM으로 암호화해 기기에 저장하며 프로젝트 JSON/소스에 포함하지 않습니다. AI 설정에서 키를 비워 저장하면 삭제됩니다.
- 사용자 요청에 따라 분석·테스트·실기기/실제 API 호출 검증은 생략했습니다. GitHub Actions가 업로드 후 Android APK를 자동 빌드합니다.

## 빌드 수정

재생 원본 주소 사용 변경에 맞춰 실패 진단 테스트의 확인 필드를 playAddr로 수정했습니다.

## 0.2.4 — 재생 원본 주소 사용

- 공개 페이지가 제공하는 playAddr를 사용합니다. 워터마크 포함 가능성이 있는 downloadAddr로 대체하지 않습니다.
- 비공개·명시적 다운로드 비활성화 검사와 HTTPS 도메인 제한을 유지합니다. 원본 주소가 없으면 파일 연결을 안내합니다.
- 주소의 실제 워터마크 유무는 보장하지 않습니다. 사용자 요청에 따라 이번 변경의 분석·테스트·실기기 검증은 생략했습니다.

## 0.2.3 — TikTok 모바일 공유 페이지 구조 지원

- 사용자가 제공한 실패 링크 응답을 확인해 원인을 재현했습니다. HTTP 200 JSON의 영상 정보는 `webapp.reflow.video.detail`에 있지만 기존 파서는 `webapp.video-detail`만 조회했습니다.
- 두 구조에서 요청한 영상 ID와 일치하는 항목만 읽습니다. 기존 다운로드 허용·도메인 검사도 유지합니다.
- 실제 응답의 구조를 익명화한 테스트 fixture로 회귀 테스트를 추가했습니다.
- 제공된 링크의 downloadAddr에서 HTTP 200 video/mp4, 2,393,637 bytes 다운로드를 확인했습니다. ffprobe: H.264/AAC, 576×1024, 11.655초. 이는 작업 환경의 다운로드 검증이며 Android 실기기 실행은 별도 확인이 필요합니다.

## 0.2.2 — 보안 확인 오판 수정

- HTML 스크립트에 captcha라는 단어가 있는 것만으로 보안 확인 페이지로 판정하지 않습니다.
- 영상 메타데이터 없음 / 다운로드 주소 없음 / 비공개 / 다운로드 비활성화를 구분합니다.
- 오류 정보에 메타데이터 JSON 해석·영상 ID 일치·다운로드 주소 존재 여부와 숫자 상태 코드를 기록합니다. 쿠키·서명 URL·HTML 원문은 기록하지 않습니다.
- 실제 실패 링크가 제공되지 않아 해당 영상 다운로드 성공은 아직 검증하지 못했습니다.

## 0.2.1 다운로드 진단 업데이트

- 확인된 코드 문제: 응답에 Set-Cookie가 없으면 기존 쿠키를 지우던 동작 수정. 도메인·경로·만료 조건을 지키며 쿠키 유지.
- 링크·페이지 확인에 45초 제한, 파일 다운로드에 3분 제한 적용. 대기시간 초과 시 요청 종료.
- 실패 메시지에 PAGE/MEDIA/FILE 단계, HTTP 상태·응답 타입·본문 크기 추가.
- 오류 정보 복사 버튼 추가. 쿠키·서명된 다운로드 URL·인증 값은 진단에 포함하지 않음.
- 단위 테스트는 쿠키 유지·도메인 경계·경로·삭제 처리 확인.
- 사용자가 보고한 링크의 실패 원인은 아직 재현하지 못함. 실패 링크·오류 코드로 실전 검증 필요.

## 0.2 업데이트 — TikTok 링크에서 원본 다운로드

- 링크 추가 또는 Android 공유로 등록하면 공개 영상 페이지의 `downloadAddr`에서 MP4 다운로드를 시도합니다.
- 별도 AI API·서버 없이 휴대폰에서 처리합니다. 워터마크는 제거하지 않습니다.
- 다운로드 진행률·취소·재시도·실패 사유·수동 파일 연결을 지원합니다.
- TikTok의 공식 다운로드 API가 아닙니다. 페이지 변경·로그인·지역·요청 제한으로 실패할 수 있습니다. 모든 링크 다운로드를 보장하지 않습니다.
- 재생 전용 주소를 다운로드 주소로 대신 사용하거나 비공개·인증·요청 제한을 우회하지 않습니다.
- 성공한 파일은 앱 전용 원본 저장소에 보관하고 카드 클릭으로 편집합니다. 편집 결과의 갤러리 저장은 기존과 같습니다.
- `shorts-studio-source.zip`에 소스가 들어 있습니다. 루트 워크플로는 압축을 `app/`에 풀어 빌드합니다.
- GitHub Actions → Android debug APK → Run workflow로 빌드를 다시 실행할 수 있습니다. 성공한 실행의 Artifacts에서 APK를 받습니다.
- 0.2 라이브 TikTok 다운로드는 실제 기기·링크로 확인해야 합니다. 빌드·파서 테스트 통과와 실제 다운로드 성공은 별개입니다.

# Shorts Studio — Android MVP 0.2

15초 내외 영상을 수집함에서 선택하고, 템플릿·제목·상황 자막을 적용해 MP4로 저장하는 Flutter 앱의 첫 구현입니다.

**상태: 소스 구현 / APK 빌드·실기기 검증 전.** 이 파일 묶음은 설치 APK가 아닙니다. 작성 환경에 Flutter·Android SDK 및 브라우저 실행 파일이 없고 SDK 다운로드가 차단되어, Flutter 분석·테스트·컴파일과 네이티브 출력 품질을 확인하지 못했습니다.

## 이번 버전에 들어간 것

| 기능 | 구현 범위 |
|---|---|
| 공유로 수집 | Android 공유 메뉴의 텍스트(TikTok URL)·영상 파일 받기 |
| TikTok 정보 | 공식 oEmbed로 제목·제작자 조회 시도. 실패하면 링크를 유지 |
| 자동 수집 | 사용자가 선택한 기기 폴더의 새 영상, 앱이 실행 중일 때 15초 간격 검사 및 재진입 시 검사 |
| 영상 가져오기 | 시스템 파일 선택기, 앱 전용 공간에 복사, 썸네일 생성 |
| 자동 편집 | 영상 클릭 시 기본 템플릿 적용. 제목은 파일명으로 초기화 |
| 편집 | 미니멀/볼드/블루 3종, 제목·상황 자막, 구간 자르기, 중앙 채우기 또는 원본 맞춤, 음소거 |
| 저장 | Media3로 1080×1920 H.264/AAC MP4 합성, 갤러리 Movies/ShortsStudio에 저장 |
| 프로젝트 | 앱 전용 JSON 원자적 교체 저장. 공유 수집함은 확인 응답 후 제거 |
| 출력 UX | 실제 렌더링 진행률(제공되지 않으면 미정 진행), 취소, 오류, 저장 완료 알림 |

**아직 구현하지 않은 핵심 범위:** TikTok 전체 영상 자동 검색·원본 자동 다운로드. 폴더 수집은 이미 기기에 확보한 파일을 대상으로 하며 TikTok 수집 서비스와 다릅니다. TikTok API 계정 인증도 연결하지 않았습니다. 일반 공개 영상 자동 수집을 완료했다고 해석하면 안 됩니다.

외부 AI API, 온디바이스 AI 분석, 대사 인식, 자동 상황 이해, YouTube 업로드, iOS 영상 엔진, 앱 종료 중 백그라운드 수집은 포함하지 않았습니다.

## 실행

필요 환경: Flutter 3.44 이상 stable (Dart 3.12 이상), Android Studio/SDK, JDK 17, Python 3, Android 10(API 29) 이상 기기. 패키지 다운로드를 위한 인터넷이 필요합니다.

압축을 풀고 `shorts_studio` 디렉터리에서:

```bash
python tool/bootstrap.py
flutter analyze
flutter test
flutter run
```

Windows에서 `python` 명령이 없으면 `py tool/bootstrap.py`를 사용합니다. `tool/bootstrap.py`는 Flutter SDK 버전에 맞는 Android 뼈대를 생성하고 네이티브 코드·매니페스트·의존성을 설치합니다. Gradle/Kotlin 플러그인 설정은 설치된 Flutter의 기본값을 유지합니다.

APK 만들기:

```bash
flutter build apk --debug
```

결과: `build/app/outputs/flutter-apk/app-debug.apk`. 개발용 디버그 빌드이며 앱스토어 출시 서명은 포함하지 않습니다.

GitHub 저장소의 루트에 이 폴더 **내용**을 올리면 `.github/workflows/android.yml`로 테스트와 APK 빌드를 실행할 수 있습니다. 코드는 저장소에 업로드하지 않았으며 워크플로도 실행되지 않았습니다. Actions 완료 후 `shorts-studio-debug-apk` 아티팩트에서 APK를 받습니다.

## 사용 순서

1. `샘플 영상으로 시작` 또는 `영상 가져오기`.
2. 자동 수집을 쓰려면 우측 상단 설정 → 수집 폴더 선택. Android 정책상 루트 Download 등을 선택할 수 없으면 별도 하위 폴더를 만듭니다.
3. TikTok에서 공유 → Shorts Studio를 선택하면 링크가 수집함에 추가됩니다. 앱 목록에서 보이지 않으면 링크 복사 → 앱의 `링크 추가`를 사용합니다.
4. 링크 카드에 원본이 없으면 파일을 한 번 연결합니다. 링크만으로 영상 파일을 내려받지는 않습니다.
5. 영상 카드 탭 → 기본 템플릿 적용 → 제목·자막·구간 확인 → `MP4로 저장`.
6. 갤러리의 Movies/ShortsStudio에서 결과 확인. 저장함 카드로 편집을 다시 열 수 있습니다.

저장 중에는 앱을 켜두세요. OS가 앱을 종료하면 작업을 다시 시작해야 합니다. 강제 종료 중인 작업의 이어서 렌더링은 미지원입니다.

## 디자인

사용자가 제공한 See for Yourself 디자인 토큰을 적용했습니다.

- 흰색 #FFFFFF, 검정 #101010/#000000, 파랑 #0099FF.
- 회색 #C6C6C6, 절제된 구분선, 8px 중심 간격.
- 큰 얇은 헤드라인, 둥근 카드, 알약형 버튼.
- 수집함 → 편집 → 갤러리 저장, 업로드 탭 없음.
- Inter Display/PP Neue Montreal 폰트 바이너리·라이선스가 제공되지 않아 시스템 sans-serif를 사용합니다. 원본 폰트를 무단 번들하지 않았습니다.

`design/preview.html`은 두 화면을 비교하는 **별도 HTML 디자인 미리보기**입니다. 브라우저에서 열면 템플릿·제목·자막·영상 재생·기기 파일 미리보기를 조작할 수 있습니다. Flutter를 실행한 캡처가 아니며 이 HTML은 실제 MP4 저장을 하지 않습니다. 버튼은 그 한계를 안내합니다. 샘플 영상은 코드로 직접 만든 15초 모션 그래픽이고 TikTok 영상이 아닙니다.

- `native/android/MainActivity.kt`: SAF 파일·폴더, 메타데이터, 공유, Media3, MediaStore
- `tool/bootstrap.py`: Flutter 플랫폼 생성·네이티브 설치
- `.github/workflows/android.yml`: 분석·테스트·디버그 APK 빌드

미리보기 자막 레이어를 PNG로 캡처하여 동일한 레이어를 Media3에 전달합니다. OS별 텍스트 재조판 차이를 줄이기 위한 구조이며, 실제 정합도는 기기 테스트가 필요합니다. 출력은 원본을 유지하는 fit이 기본값입니다. crop을 켜면 중앙 기준으로 화면을 채우므로 가장자리가 잘립니다. 자막은 전체 편집 구간 동안 표시됩니다. 별도의 자막 타이밍·발화 트랙은 아직 없습니다.

## 한계와 실기기 확인 항목

- Android만 연결되어 있습니다. Flutter UI를 공유하더라도 iOS는 별도 Swift 구현이 필요합니다.
- 0.2초~120초, 최대 512MB 입력을 처리합니다. 주요 목표는 5~30초 MP4입니다.
- 폴더는 한 단계만 검사합니다. SAF 권한이 취소되면 다시 선택해야 합니다.
- 기본 15초 간격은 스케줄 목표이며 폴더 IO 시간·OS 중단에 따라 늦어집니다.
- 새 파일의 이름/URI/크기/수정시각으로 중복을 줄입니다. 같은 영상의 별도 복사본까지 해시로 제거하지 않습니다.
- 무음 원본에 AAC 트랙을 새로 만들지는 않습니다.
- HDR·회전 메타데이터·저장 공간 부족·저사양 인코더는 아직 검증되지 않았습니다.
- 앱 삭제 시 원본 사본·프로젝트 정보는 삭제됩니다. 갤러리에 내보낸 영상은 별개입니다.
- 원본 영상·음악의 이용 범위는 사용자가 확인합니다. 현재 버전은 권리 증빙 DB와 발행 기능이 없습니다.

### 빌드 후 필수 확인

1. 세로 H.264 15초 영상: 제목·자막이 미리보기와 저장본에 동일하게 나타나는지.
2. 가로 영상: fit은 전체 보존, crop은 중앙 잘림이 일치하는지.
3. 구간 2~8초: 저장본 길이가 약 6초인지, 음소거를 켜면 오디오가 없는지.
4. 한글·긴 제목·빈 제목·세 템플릿을 확인.
5. 앱 종료 후 프로젝트 복원, 콜드/웜 공유 인텐트, 동일 URL 중복 처리.
6. 폴더 파일 추가 → 수집 → 다시 스캔해도 중복 생성되지 않는지.
7. 저장 취소·공간 부족·인코더 오류 때 성공으로 표시하지 않는지.
8. 저사양 실기기에서 1080p 출력·온도·메모리·발열 확인.
